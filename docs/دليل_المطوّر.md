# دليل المطوّر — تطبيق «لا تجلس طويلًا»

مرجع تقنيّ لأي مطوّر (أو جلسة Claude لاحقة) يريد فهم المشروع والبناء عليه بسرعة.
للسياق وطلب المالك وقرارات التصميم راجع `docs/السياق_والمتطلبات.md`، وللقواعد
السريعة راجع `CLAUDE.md`. **كل التطوير يتمّ في `alaoufi/health_reminder`.**

---

## 1) نظرة عامة

- **الاسم/الشعار:** لا تجلس طويلًا — `applicationId: com.alaoufi.health_reminder`.
- **النوع:** تطبيق Flutter مستقلّ (أندرويد فقط)، عربيّ RTL، **بلا إنترنت وبلا حسابات**.
- **الغرض:** تذكير صحّيّ بكسر الجلوس عبر **شاشة تغطية صامتة** (خلفيات متغيّرة +
  عبارات + عدّاد) تقتحم الجهاز في وقت الراحة، ولا تُغلق إلا بانتهاء المدّة أو رمز.
- **التوقيت:** مثبّت على `Asia/Riyadh` (بلا `flutter_timezone` — تكسر البناء).

---

## 2) الإعداد المحليّ والبناء

```bash
flutter pub get
flutter analyze                 # يجب أن يكون بلا أخطاء (يفحصه CI أيضًا)
flutter test                    # اختبارات النموذج
dart run flutter_launcher_icons # توليد الأيقونات من assets/icon
flutter build apk --release --split-per-abi
```

- Flutter المثبّت في CI: **3.44.8 stable**، Java **17 (Temurin)**.
- الأيقونات تُولَّد من `assets/icon` قبل كل بناء (adaptive + legacy).

## 4) نموذج الجدولة (المرساة/الدورة) — الأهمّ

الفكرة: **دورة متدحرجة** بدل ربطها ببداية النافذة.

- **المرساة (`_anchor`)** = لحظة بداية شوط العمل الحاليّ.
- **الراحة القادمة = المرساة + مدّة العمل** (`workMinutes`).
- عند بدء الراحة: نهايتها تصبح المرساة الجديدة (تتدحرج الدورة) — `beginOverlay → setAnchor(end)`.
- عند حفظ الإعدادات وهي مفعّلة: المرساة تُضبط على «الآن» (يبدأ العدّ من لحظة الحفظ).
- النوافذ تدعم **عبور منتصف الليل** (بداية > نهاية) عبر `_windowAround`.
- إن فاتت راحة تمامًا: `_nextBreak` **يتقدّم بدورات كاملة** (عمل+راحة) إلى أوّل راحة
  غير فائتة عبر حلقة `while` — **لا يُعيد الضبط إلى «الآن» في كل رسم**.

### ⚠️ مزلقان سبّبا العدّاد المُجمَّد على 59:59 (لا تُعِدهما)

1. **إعادة الضبط في كل رسم:** لو أعاد `_nextBreak` حساب `nb = now + work` عند كل
   استدعاء (والرئيسية تستدعيه كل ثانية)، يبقى الفرق ثابتًا = مدّة العمل بلا تناقص.
   الحلّ: التقدّم بدورات من مرساة **ثابتة**.
2. **مرساة مفقودة (`_anchor == null`) مع التفعيل:** التعبير `_anchor ?? now` يُنتج
   «الآن» جديدة كل رسم ⇒ تجمّد. الحلّ المطبّق: في `load()` و`reloadAnchor()`، إن كان
   مفعّلًا بلا مرساة محفوظة، **تُثبَّت المرساة على «الآن» مرّة واحدة وتُحفَظ**.

**القاعدة:** المرساة نقطة زمنيّة **ثابتة ومحفوظة**؛ لا تُشتقّ من «الآن» عند القراءة.

## 5) جسر Dart ↔ Native عبر SharedPreferences

الملفّ الأصليّ: `FlutterSharedPreferences`، والمفاتيح من Dart تُخزَّن بسابقة
`flutter.` (مثال: `hr_next_ms` في Dart = `flutter.hr_next_ms` في Kotlin). أعداد
Dart تُخزَّن كـ`Long`.

| المفتاح | يكتبه | يقرؤه | المعنى |
|---|---|---|---|
| `hr_enabled` | Dart | Dart/Native | التفعيل العامّ. |
| `hr_periods` | Dart | Dart | الفترات (JSON). |
| `hr_anchor` | Dart/Native | Dart | مرساة الدورة (ms). |
| `hr_next_ms` | Dart/Native | Native | موعد الراحة القادمة (ms) — تفحصه الخدمة. |
| `hr_work_ms` / `hr_rest_ms` / `hr_idle_ms` | Dart | Native | مدّد العمل/الراحة/عتبة الخمول (ms). |
| `hr_break_active` | Dart | Native | راحة نشطة الآن (يمنع الازدواج). |
| `hr_screen_off_at` | Native | Native | لحظة إطفاء الشاشة (لمنطق الخمول). |
| `hr_active_end` / `hr_active_minutes` | Dart | Dart | خطّ أمان لعرض القفل. |
| `hr_sound_alert` / `hr_show_phrases` / `hr_bypass_code` / `hr_idle_reset` | Dart | Dart | خيارات. |
| `hr_autostart_done` | Dart | Dart | إخفاء بطاقة التشغيل التلقائيّ بعد تفعيلها. |

> عند أي تغيير للجدولة من Dart، استدعِ `writeNativeState()` كي تلتقطه الخدمة/المنبّه.
> وعند العودة للتطبيق، استدعِ `reloadAnchor()` (يفعل `sp.reload()`) لالتقاط ما كتبه native.

## 6) آليّة الاقتحام والأذونات (Android 12/13/14 + MIUI)

الاقتحام موثوق عبر **ثلاث دعائم متكاملة**:

1. **`AlarmManager.setAlarmClock`** (رمز الطلب 7100): أعلى المنبّهات أولويّةً،
   تحترمه شاومي حتى في توفير الطاقة. المُستقبِل **يعيد جدولة نفسه** فتبقى السلسلة
   مستقلّة عن بقاء التطبيق أو الخدمة.
2. **إشعار ملء الشاشة** (`fullScreenIntent`, id 9911) الصامت: يوقظ الشاشة ويفتح
   الاستراحة والجهاز مقفل. على **أندرويد 14** يُقيَّد `USE_FULL_SCREEN_INTENT`
   ويلزم منحه يدويًّا (`canUseFullScreenIntent` + `ACTION_MANAGE_APP_USE_FULL_SCREEN_INTENT`).
3. **خدمة أماميّة دائمة** (`specialUse`) تفتح الاستراحة أثناء استخدام تطبيق آخر
   (تفحص `hr_next_ms` كل ٢ث).

**الأذونات الحاسمة التي يجب أن يمنحها المستخدم** (بطاقاتها في الرئيسية تختفي عند المنح):

| الإذن | لماذا |
|---|---|
| **العرض فوق التطبيقات** (`SYSTEM_ALERT_WINDOW`) | يمنح Background Activity Launch على أندرويد 12+ — **الشرط الحاسم** للاقتحام فوق تطبيق آخر (يوتيوب مثلًا). |
| **إشعارات ملء الشاشة** (أندرويد 14) | الاقتحام والجهاز مقفل بدل إشعار عاديّ. |
| **بلا قيود بطاريّة** (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) | يمنع النظام من قتل الخدمة. |
| **التشغيل التلقائيّ (Autostart)** على MIUI | لتعمل الخدمة/المنبّه والتطبيق مغلق. |
| **قفل التطبيق في المهامّ الأخيرة** | كي لا يُنظَّف من الذاكرة. |

> **قيد نظاميّ:** تطبيق عاديّ (بلا Device Owner) لا يمنع زرّ الهوم/الطاقة منعًا
> تامًّا؛ نُنفّذ أقصى ما يسمح به النظام (إعادة إظهار الاستراحة في `onUserLeaveHint`).

## 7) النسخ الاحتياطيّ والاستعادة

- `backup_service.dart` يكتب الإعدادات تلقائيًّا في **ملفّ مخفيّ** (عبر
  `MANAGE_EXTERNAL_STORAGE`) ينجو من إلغاء التثبيت.
- عند تثبيت جديد (`_wasFresh == true`: لا `hr_periods` محفوظة) يحاول الاستعادة عند
  منح إذن الوصول للملفّات.

## 8) التحديث الذاتيّ

- CI ينشر `version.json` في إصدار **`latest`** الثابت:
  `{"version":"1.2.<run>","build":<run>,"url":".../HealthReminder.apk"}`.
- `update_service.dart` يقرؤه ويقارن، و`force_update_gate.dart` يعرض بوّابة التحديث.
- رابط التنزيل الدائم: `releases/download/latest/HealthReminder.apk`.

## 9) CI/CD والتوقيع (مُعَدّ ويعمل)

الملفّ: `.github/workflows/build-apk.yml` — يعمل **عند كل دفع إلى `main`** (و`workflow_dispatch`):

1. يجهّز التوقيع من أسرار المستودع (إن وُجدت)، وإلا يتراجع لـdebug مع تحذير.
2. `flutter pub get` → توليد الأيقونات → `flutter build apk --split-per-abi`.
3. رقم البناء = `1000 + run_number` (متصاعد دائمًا).
4. اسم النسخة = `1.2.<run_number>`.
5. ينشر `HealthReminder.apk` (arm64) + `HealthReminder-armeabi-v7a.apk` + `version.json`
   إلى إصدار `latest`.

### التوقيع الثابت (لِتُثبَّت التحديثات فوق القديم بلا حذف)

المفتاح ثابت الآن. الأسرار الأربعة مضبوطة في **Settings → Secrets and variables → Actions**:

| السرّ | المحتوى |
|---|---|
| `KEYSTORE_BASE64` | ملفّ `.jks` مُرمَّزًا base64 (سطر واحد). |
| `STORE_PASSWORD` | كلمة مرور المتجر. |
| `KEY_ALIAS` | اسم المفتاح (`health`). |
| `KEY_PASSWORD` | كلمة مرور المفتاح. |

- سجلّ الخطوة يطبع `✅ سيُوقَّع الإصدار بمفتاح النشر الثابت.` عند النجاح.
- **⚠️ حرجٌ:** ملفّ `health-release.jks` (المفتاح الخاصّ) يجب حفظه نسخةً احتياطيّة
  آمنة. لو ضاع، **يستحيل** التحديث فوق النسخة المثبّتة (يلزم إلغاء تثبيت المستخدمين).
- ملفّ `android/key.properties` **غير متعقَّب** (يُولَّد في CI من الأسرار).
- إنشاء مفتاح جديد (مرجع):
  ```bash
  keytool -genkeypair -keystore health-release.jks -alias health \
    -keyalg RSA -keysize 2048 -validity 10950 \
    -storepass <PASS> -keypass <PASS> -dname "CN=...,O=...,C=SA"
  base64 -w0 health-release.jks   # القيمة لـ KEYSTORE_BASE64
  ```

## 10) القواعد الثابتة (لا تكسرها)

- **بلا صوت ولا اهتزاز** في أي تنبيه (الجرس **اختياريّ** ومطفأ افتراضيًّا).
- عربيّة RTL وبساطة الاستخدام.
- **لا تُعِد** `flutter_timezone` (تعارض JVM يكسر البناء) — التوقيت مثبّت `Asia/Riyadh`.
- المرساة نقطة زمنيّة ثابتة محفوظة (راجع §4 — مزالق 59:59).
- ارفع `versionCode` في كل إصدار (يتكفّل به CI عبر `1000 + run_number`).
- **بعد أي تحديث:** حدِّث «سجلّ التحديثات» في `docs/السياق_والمتطلبات.md`.

---

## 11) منهجيّة الإصدار (كيف تُكمل العمل)

1. طوّر على فرع مخصّص، شغّل `flutter analyze` (لا أخطاء).
2. حدِّث «سجلّ التحديثات» في `docs/السياق_والمتطلبات.md`.
3. ادفع → افتح PR → ادمج (squash) إلى `main`.
4. الدمج يُطلق البناء تلقائيًّا؛ راقب نجاحه.
5. حمّل `HealthReminder.apk` من إصدار `latest` وسلّمه للمالك.
6. أشياء تحتاج **اختبارًا على الجهاز** (لا تُثبَت بـCI): موثوقيّة الاقتحام على MIUI،
   سلوك الخدمة والبطاريّة، إعادة إظهار القفل، النسخ الاحتياطيّ عبر إعادة التثبيت.
